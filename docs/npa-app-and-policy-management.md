# NPA Private App and Policy Management via Terraform

> **Reference examples:**
> - [terraform-netskope-examples](https://github.com/jharris-ns/terraform-netskope-examples) — working Terraform configurations
> - [terraform-provider-netskope](https://github.com/jharris-ns/terraform-provider-netskope) — provider source and full schema docs

---

## Overview

The Netskope Terraform provider exposes the full NPA app and policy stack as first-class resources.
This document covers how to define private apps for different access patterns, associate them to
publishers, and write access policy rules — all in Terraform.

The approach described here follows a **tag-driven policy model**: apps are tagged by type and team,
and policy rules target those tags dynamically. This decouples app inventory management from policy
authorship — adding a new app with the right tag automatically includes it in the correct rules
without touching the policy layer.

---

## Key Resources

| Resource / Data Source | Purpose |
|---|---|
| `netskope_npa_private_app` | Define a private app and associate it to publishers |
| `netskope_npa_rules` | Create an NPA access policy rule |
| `data.netskope_npa_publishers_list` | Look up existing publishers by name |
| `data.netskope_npa_private_apps_list` | Look up existing apps (used for tag-based rule targeting) |

## Part 1: Private App Attribute Reference

### Required attributes

| Attribute | Type | Notes |
|---|---|---|
| `protocols` | Attributes List | Port + protocol (tcp/udp). Required for **all** app types. |

### Optional attributes (commonly used)

| Attribute | Type | Default | Notes |
|---|---|---|---|
| `private_app_name` | String | — | Human-readable name. Requires replacement if changed. |
| `private_app_hostname` | String | — | Hostname users connect to via the NPA client. Set by you for client-based apps; auto-generated by Netskope for browser-based apps — do not set. |
| `private_app_protocol` | String | — | Application-layer scheme: `"http"` or `"https"`. **Browser-based only.** Requires replacement if changed. |
| `real_host` | String | — | Backend FQDN that the publisher proxies to. **Browser-based only.** Must be an FQDN — IPs are rejected for HTTPS apps. |
| `clientless_access` | Boolean | `false` | `true` = browser-based (no NPA client). `false` = NPA client access. |
| `publishers` | Attributes List | — | List of `{publisher_id, publisher_name}` objects. |
| `tags` | Attributes List | — | List of `{tag_name}` objects. Case-sensitive. |
| `use_publisher_dns` | Boolean | `false` | Publisher resolves DNS for `real_host`. Recommended `true` for split-DNS environments. |
| `trust_self_signed_certs` | Boolean | `false` | Accept self-signed backend TLS certificates. |
| `is_user_portal_app` | Boolean | `false` | Show in the Browser Access User Portal. Requires User Portal license. |
| `hide_app_in_portal` | Boolean | — | Hide from portal listing. **Browser-based only.** |
| `allow_unauthenticated_cors` | Boolean | `false` | Allow CORS OPTIONS requests without auth. **Browser-based only.** |
| `allow_uri_bypass` | Boolean | — | Enable URI auth bypass paths. **Browser-based only.** Feature-flagged. |
| `bypass_uris` | List of String | — | URI paths that skip SAML auth (max 20). **Browser-based only.** |
| `uribypass_header_value` | String | — | Shared secret for `X-NSKP-URIBYPASS` header (8–64 chars). **Browser-based only.** |
| `upgrade_insecure_requests` | Boolean | — | Upgrade HTTP to HTTPS at the proxy. Requires `enterprise_browser = true`. **Browser-based only.** |
| `paths` | List of String | — | Sub-paths to include in the app scope. |

### Read-only attributes (computed by Netskope)

| Attribute | Notes |
|---|---|
| `private_app_id` | Netskope-assigned numeric ID. Used when referencing in other resources. |
| `custom_host` | Friendly FQDN derived from a certificate CN uploaded via the Netskope UI. Cannot be set via Terraform. |

### `protocols` nested schema

```hcl
protocols = [
  {
    port     = "443"   # String, not number
    protocol = "tcp"   # "tcp" or "udp"
  }
]
```

> **Protocol ordering**: List multiple protocols in ascending port order. The API may return them in
> a different order, causing spurious plan diffs if not sorted. Provider v0.4.0+ auto-sorts on read,
> but listing sorted in config is still best practice for readability.

### `publishers` nested schema

```hcl
publishers = [
  {
    publisher_id   = "12345"         # String — use tostring() when referencing resource attributes
    publisher_name = "gcp-us-west-1" # String
  }
]
```

## Part 2: Client-Based vs Browser-Based Apps

These two access modes use **mutually exclusive field sets**. Mixing fields across modes causes API
errors or silent misbehavior.

| | Client-Based (NPA tunnel) | Browser-Based (clientless) |
|---|---|---|
| **`clientless_access`** | `false` (default) | `true` |
| **`private_app_hostname`** | Set by you — hostname users connect to | Auto-generated by Netskope — **do not set** |
| **`private_app_protocol`** | **Do not set** | Required: `"http"` or `"https"` |
| **`real_host`** | **Do not set** | Required: backend FQDN (no IPs for HTTPS) |
| **Endpoint requirement** | Netskope client installed | Browser only |
| **Protocols** | Required — any port/tcp/udp | Required — single tcp entry matching `private_app_protocol` port |
| **Browser-only fields** | **Do not set** | `hide_app_in_portal`, `allow_uri_bypass`, `bypass_uris`, etc. |

> **If you need both access methods for the same resource:** create two separate app definitions —
> one client-based and one browser-based — pointing to the same backend.

## Part 3: App Examples by Type

### Client-Based: SSH Access

```hcl
resource "netskope_npa_private_app" "ssh_bastion" {
  private_app_name     = "prod-ssh-bastion"
  private_app_hostname = "bastion.prod.internal" # Hostname users connect to via NPA client

  # clientless_access = false (default) — NPA client required, no browser access
  # Do NOT set real_host or private_app_protocol for client-based apps
  clientless_access  = false
  is_user_portal_app = false
  use_publisher_dns  = true

  protocols = [
    {
      port     = "22"
      protocol = "tcp"

  publishers = local.app_publishers

  tags = [
    { tag_name = "managed-by-terraform" },
    { tag_name = "production" },

  ]
}
```

### Browser-Based: HTTPS Web App

Browser-based apps proxy the user's browser to a backend service via the Netskope portal. No NPA
client required. `private_app_hostname` is **auto-generated** — do not set it.

```hcl
resource "netskope_npa_private_app" "jira" {
  private_app_name = "prod-jira"

  # Browser-based — do NOT set private_app_hostname (auto-generated by Netskope)
  private_app_protocol = "https"  # Application-layer scheme: "http" or "https" only
  real_host            = "jira.internal.example.com"  # FQDN required — IPs rejected for HTTPS

  clientless_access          = true
  is_user_portal_app         = false  # Set true only with User Portal license
  use_publisher_dns          = true
  trust_self_signed_certs    = false
  allow_unauthenticated_cors = false

  protocols = [
    {
      port     = "443"  # Must match private_app_protocol: https=443, http=80
      protocol = "tcp"
    }
  ]

  publishers = local.app_publishers

  tags = [
    { tag_name = "managed-by-terraform" },
    { tag_name = "production" },
    { tag_name = "web-tier" },
    { tag_name = "team-engineering" },
  ]
}
```

### Browser-Based: URI Authentication Bypass

Useful for API endpoints, webhooks, or health checks that cannot carry SAML auth cookies. Requests
to the listed URIs skip authentication if they include the `X-NSKP-URIBYPASS` header with the
configured secret value. **Feature-flagged** — contact Netskope Support to enable on your tenant.

```hcl
resource "netskope_npa_private_app" "api_gateway" {
  private_app_name     = "prod-internal-api"
  private_app_protocol = "https"
  real_host            = "api.internal.example.com"

  clientless_access  = true
  is_user_portal_app = false
  hide_app_in_portal = true  # API backend — no need to show in portal
  use_publisher_dns  = true

  allow_uri_bypass = true

  # URI paths that skip SAML auth — up to 20 per app
  # Regular expressions not supported. A bare "/" is not supported.
  bypass_uris = [
    "/api/v1/webhooks/github",
    "/api/v1/webhooks/slack",
    "/healthz",
  ]

  # Shared secret for X-NSKP-URIBYPASS header — treat as sensitive
  # curl example: curl -H 'X-NSKP-URIBYPASS: <value>' https://<app-hostname>/healthz
  uribypass_header_value = var.api_bypass_secret

  protocols = [
    {
      port     = "443"
      protocol = "tcp"
    }
  ]

  publishers = local.app_publishers

  tags = [
    { tag_name = "managed-by-terraform" },
    { tag_name = "production" },
    { tag_name = "web-tier" },
    { tag_name = "api" },
  ]
}
```

### Custom Hostname for Browser Apps

The `custom_host` attribute (a friendly FQDN like `jira.company.com`) is **read-only** in the
Terraform provider — it cannot be set via the API. The workflow is:

1. Create the browser app via Terraform (generates a Netskope-hosted URL)
2. In the Netskope UI, upload a certificate/key pair whose CN is your desired friendly FQDN
3. Create a DNS CNAME from your friendly FQDN to the Netskope-generated `private_app_hostname`
4. Run `terraform refresh` — `custom_host` will appear in state as a computed attribute

The certificate upload uses a legacy UI endpoint not exposed in the v2 REST API, so this step
cannot currently be automated.

## Part 4: Publisher Association

### Pattern A: Publishers in the same Terraform configuration

Reference publisher resources directly when they are defined in the same workspace:

```hcl
resource "netskope_npa_publisher" "primary" {
  publisher_name = "gcp-us-west-1"
}

resource "netskope_npa_publisher" "secondary" {
  publisher_name = "gcp-us-west-2"
}

locals {
  # publisher_id must be a string — tostring() converts from the number the API returns
  app_publishers = [
    {
      publisher_id   = tostring(netskope_npa_publisher.primary.publisher_id)
      publisher_name = netskope_npa_publisher.primary.publisher_name
    },
    {
      publisher_id   = tostring(netskope_npa_publisher.secondary.publisher_id)
      publisher_name = netskope_npa_publisher.secondary.publisher_name
    },
  ]
}
```

### Pattern B: Look up publishers that already exist in the tenant

Use the data source when publishers are managed separately or were created outside Terraform:

```hcl
data "netskope_npa_publishers_list" "all" {}

locals {
  primary_publisher = [
    for p in data.netskope_npa_publishers_list.all.data.publishers :
    p if p.publisher_name == var.primary_publisher_name
  ][0]

  secondary_publisher = var.secondary_publisher_name != "" ? [
    for p in data.netskope_npa_publishers_list.all.data.publishers :
    p if p.publisher_name == var.secondary_publisher_name
  ][0] : null

  # Conditionally build single or dual-publisher list for HA
  app_publishers = var.secondary_publisher_name != "" ? [
    {
      publisher_id   = tostring(local.primary_publisher.publisher_id)
      publisher_name = local.primary_publisher.publisher_name
    },
    {
      publisher_id   = tostring(local.secondary_publisher.publisher_id)
      publisher_name = local.secondary_publisher.publisher_name
    },
    ] : [
    {
      publisher_id   = tostring(local.primary_publisher.publisher_id)
      publisher_name = local.primary_publisher.publisher_name
    }
  ]
}
```

Either pattern produces the same `local.app_publishers` structure and can be used interchangeably
in any app's `publishers` block.

## Part 5: Managing Apps at Scale with `for_each`

For 5+ apps of the same type, define them from a variable map rather than repeating resource
blocks. This is the recommended pattern.

### Variable definition

```hcl
# variables.tf
variable "client_apps" {
  description = "Client-based private apps (SSH, RDP, database, TCP)"
  type = map(object({
    hostname   = string       # NPA client hostname
    port       = string       # Port as string
    protocol   = optional(string, "tcp")
    extra_tags = optional(list(string), [])
  }))
  default = {}
}

variable "browser_apps" {
  description = "Browser-based private apps (HTTPS proxy via Netskope portal)"
  type = map(object({
    real_host  = string             # Backend FQDN (HTTPS requires FQDN, not IP)
    port       = optional(string, "443")
    app_proto  = optional(string, "https")  # "http" or "https"
    extra_tags = optional(list(string), [])
  }))
  default = {}
}
```

### Resource blocks

```hcl
# apps-client.tf
resource "netskope_npa_private_app" "client" {
  for_each = var.client_apps

  private_app_name     = "${var.environment}-${each.key}"
  private_app_hostname = each.value.hostname

  clientless_access  = false
  is_user_portal_app = false
  use_publisher_dns  = true

  protocols = [
    {
      port     = each.value.port
      protocol = each.value.protocol
    }
  ]

  publishers = local.app_publishers

  tags = concat(
    [
      { tag_name = "managed-by-terraform" },
      { tag_name = var.environment },
    ],
    [for t in each.value.extra_tags : { tag_name = t }]
  )
}

# apps-browser.tf
resource "netskope_npa_private_app" "browser" {
  for_each = var.browser_apps

  private_app_name     = "${var.environment}-${each.key}"
  private_app_protocol = each.value.app_proto
  real_host            = each.value.real_host

  clientless_access  = true
  is_user_portal_app = false
  use_publisher_dns  = true

  protocols = [
    {
      port     = each.value.port
      protocol = "tcp"
    }
  ]

  publishers = local.app_publishers

  tags = concat(
    [
      { tag_name = "managed-by-terraform" },
      { tag_name = var.environment },
      { tag_name = "web-tier" },
    ],
    [for t in each.value.extra_tags : { tag_name = t }]
  )
}
```

## Part 7: Policy Rules

### How NPA rule evaluation works

NPA policy uses **most-specific-match** semantics — not top-to-bottom evaluation. A rule matching
on user group + device posture + app wins over a rule matching on app alone, regardless of list
position. `rule_order` controls UI list placement for readability, not evaluation priority.

### Explicit rules (named apps)

Best for a small number of well-known apps or one-off rules:

```hcl
resource "netskope_npa_rules" "allow_jira" {
  rule_name   = "prod-allow-jira"
  enabled     = "1"
  description = "Allow all authenticated users browser access to Jira"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = {
      action_name = "allow"
    }

    # Plain string — NOT "[${app.name}]". Brackets cause "Private app [[name]] doesn't exist"
    private_apps  = [netskope_npa_private_app.jira.private_app_name]
    access_method = ["Clientless"]
    user_type     = "user"
  }

  rule_order = { order = "top" }
}
```

### Tag-driven rules (recommended for scale)

Read the live app inventory and build rule targets dynamically from tags. A new app tagged
`web-tier` is included in the web access rule automatically on the next `terraform apply`.

```hcl
# data.tf — query the live app inventory
data "netskope_npa_private_apps_list" "all" {}

locals {
  # Build name lists filtered by tag — used directly in rule private_apps
  web_apps = [
    for app in data.netskope_npa_private_apps_list.all.private_apps :
    app.private_app_name
    if length([
      for tag in coalesce(app.tags, []) :
      tag if contains(["web-tier"], tag.tag_name)
    ]) > 0
  ]

  infrastructure_apps = [
    for app in data.netskope_npa_private_apps_list.all.private_apps :
    app.private_app_name
    if length([
      for tag in coalesce(app.tags, []) :
      tag if contains(["infrastructure"], tag.tag_name)
    ]) > 0
  ]

  database_apps = [
    for app in data.netskope_npa_private_apps_list.all.private_apps :
    app.private_app_name
    if length([
      for tag in coalesce(app.tags, []) :
      tag if contains(["database-tier"], tag.tag_name)
    ]) > 0
  ]

  all_app_names = [
    for app in data.netskope_npa_private_apps_list.all.private_apps :
    app.private_app_name
  ]
}
```

```hcl
# rules.tf — tag-driven rules

# Developer access to all web-tier apps
resource "netskope_npa_rules" "developer_web_access" {
  count = length(local.web_apps) > 0 ? 1 : 0  # Guard: don't create rule with empty app list

  rule_name   = "prod-developer-web-access"
  enabled     = "1"
  description = "Allow developers browser access to all web-tier apps"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = { action_name = "allow" }

    private_apps  = local.web_apps      # Dynamically populated from tag filter
    user_groups   = var.developer_groups  # Must match IdP group names exactly
    access_method = ["Client", "Clientless"]
    user_type     = "user"
  }

  rule_order = { order = "bottom" }
}

# Platform admin: SSH and RDP
resource "netskope_npa_rules" "admin_infra_access" {
  count = length(local.infrastructure_apps) > 0 ? 1 : 0

  rule_name   = "prod-admin-infrastructure"
  enabled     = "1"
  description = "Allow platform admins SSH and RDP access"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = { action_name = "allow" }

    private_apps  = local.infrastructure_apps
    user_groups   = var.admin_groups
    access_method = ["Client"]
    user_type     = "user"
  }

  rule_order = { order = "top" }
}

# DBA team: database access
resource "netskope_npa_rules" "dba_database_access" {
  count = length(local.database_apps) > 0 ? 1 : 0

  rule_name   = "prod-dba-database-access"
  enabled     = "1"
  description = "Allow DBA team access to database tier"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = { action_name = "allow" }

    private_apps  = local.database_apps
    user_groups   = concat(var.admin_groups, var.dba_groups)
    access_method = ["Client"]
    user_type     = "user"
  }

  rule_order = {
    order   = "after"
    rule_id = tonumber(netskope_npa_rules.admin_infra_access[0].id)
  }

  depends_on = [netskope_npa_rules.admin_infra_access]
}
```

### Location-based access restriction

`net_location_obj` restricts a rule to users connecting from specific Network Locations. Network
Locations are IP ranges or subnets defined in the Netskope tenant UI under
**Policies → Network Locations**. Each location has a numeric ID — you must reference the **ID**,
not the IP address or subnet.

> **Finding the ID:** In the Netskope UI, open a Network Location and note the numeric ID in the
> URL (e.g. `.../network-location/27`). There is currently no data source to look these up
> programmatically — the ID must be copied from the UI.

```hcl
# Allow developer web access only when connecting from corporate offices
resource "netskope_npa_rules" "developer_office_only" {
  rule_name   = "prod-developer-web-office-only"
  enabled     = "1"
  description = "Developers may access web apps only from corporate network locations"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = { action_name = "allow" }

    private_apps  = local.web_apps
    user_groups   = var.developer_groups
    access_method = ["Client", "Clientless"]

    # Numeric Network Location IDs — find in Netskope UI: Policies > Network Locations
    # These are NOT IP addresses or CIDR ranges — they are the integer IDs of Location objects.
    net_location_obj      = ["27", "42"]  # e.g. "HQ Office", "London Office"
    b_negate_net_location = false         # false = must match; true = must NOT match
  }

  rule_order = { order = "bottom" }
}
```

Use `b_negate_net_location = true` to invert the match — the rule applies when the user is
**not** in any of the listed locations (useful for deny rules targeting off-network access).

```hcl
# Catch-all deny (optional — requires block action support on your tenant)
resource "netskope_npa_rules" "deny_all_other" {
  count = length(local.all_app_names) > 0 ? 1 : 0

  rule_name   = "prod-deny-all-other"
  enabled     = "1"
  description = "Explicit deny for all access not permitted above"

  rule_data = {
    policy_type  = "private-app"
    json_version = 3

    match_criteria_action = { action_name = "block" }

    private_apps  = local.all_app_names
    access_method = ["Client", "Clientless"]
    user_type     = "user"
  }

  rule_order = { order = "bottom" }

  depends_on = [
    netskope_npa_rules.developer_web_access,
    netskope_npa_rules.admin_infra_access,
    netskope_npa_rules.dba_database_access,
  ]
}
```

## Part 8: Common Mistakes and Gotchas

**`publisher_id` must be a string**

The `publishers` block requires `publisher_id` as a string. The resource and data source return it
as a number. Always wrap:

```hcl
publisher_id = tostring(netskope_npa_publisher.this.publisher_id)
```

**Do not mix client-based and browser-based fields**

Setting `real_host` or `private_app_protocol` on a client-based app (`clientless_access = false`)
causes: `"Clientless_access need to be set for non-web browser access"`. Setting
`clientless_access = true` on an app that also sets `private_app_protocol` to a non-HTTP value
turns it into a browser-proxied app and changes the generated hostname.

**Private app names in rules must NOT have brackets**

```hcl
# WRONG — "Private app [[name]] doesn't exist"
private_apps = ["[${netskope_npa_private_app.jira.private_app_name}]"]

# RIGHT
private_apps = [netskope_npa_private_app.jira.private_app_name]
```

**`real_host` must be a FQDN for browser apps using `https`**

IP addresses are rejected: `"Enter a FQDN. x.x.x.x is not a valid host"`. Use a resolvable
hostname. IPs are fine for client-based (non-HTTPS) apps.

**`private_app_name` requires replacement if changed**

Renaming an app destroys and recreates it, which removes it from any rule that referenced it by
the old name. Update rules before or simultaneously when renaming.

**`private_app_protocol` requires replacement if changed**

Changing the protocol (e.g., `"http"` → `"https"`) destroys and recreates the app. Plan
carefully — any active user sessions will be dropped.

**`port` is a string, not a number**

```hcl
port = "443"  # Right
port = 443    # Wrong — type error
```

**`count` guard on tag-driven rules**

Rules with an empty `private_apps` list are rejected by the API. The `count = length(...) > 0 ? 1 : 0`
guard prevents creating a rule when no apps match the tag filter.

**`rule_id` in `rule_order` is a number, but `.id` is a string**

```hcl
rule_order = {
  order   = "after"
  rule_id = tonumber(netskope_npa_rules.some_rule[0].id)  # tonumber() required
}
```

**`net_location_obj` takes Network Location IDs, not IP addresses**

The `net_location_obj` field in `rule_data` looks like it should accept IP ranges (the old
documentation showed examples like `"190.123.150.10"` and `"190.218.0.0/16"`). It does not.
It takes the **numeric ID** of a Network Location object, as a string:

```hcl
# WRONG — silently creates a rule that never matches
net_location_obj = ["190.123.150.10", "10.0.0.0/8"]

# RIGHT — numeric IDs of Network Location objects
net_location_obj = ["27", "42"]
```

Find the ID in the Netskope UI under **Policies → Network Locations**. The integer ID appears in
the page URL. There is no data source to look up IDs programmatically.

**User groups must match IdP values exactly**

`user_groups` values are matched against SAML/SCIM assertions at runtime. They are not validated at
plan time — an incorrect group name creates a rule that silently never matches.

**Tag names are case-sensitive**

Tags are stored with canonical casing. If your config uses `"Web-Tier"` but the tenant has
`"web-tier"`, Terraform will show drift on every plan. Use lowercase consistently.
